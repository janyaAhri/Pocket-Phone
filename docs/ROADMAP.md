## ส่วนที่ 1 — ไฟล์ใหญ่ / เซิร์ฟเวอร์หน่วง: ทำได้ไหม

### คำตอบสั้น
**ทำได้ แต่ต้องแก้ถูกจุด** และการตัดจำนวนบรรทัดไม่ใช่จุดนั้น
จำนวนบรรทัดไม่ได้ทำให้เซิร์ฟเวอร์หน่วงโดยตรง เซิร์ฟเวอร์ไม่ได้รันโค้ดมือถือ มันแค่ส่งไฟล์ให้เบราว์เซอร์ แล้วเครื่องของผู้เล่นแต่ละคนเป็นคนรัน

### ตัวเลขที่วัดจริง (ไฟล์รุ่น 2.49.0)

| ไฟล์ | ขนาดจริง | บีบอัด gzip | โหลดเมื่อไหร่ |
|---|---|---|---|
| `index.js` | 1.89 MB · 30,197 บรรทัด | 458 KB | ทุกครั้งที่เปิดหน้าเว็บ |
| `pet-assets.js` | **3.80 MB** | **2.87 MB** | **ทุกครั้งที่เปิดหน้าเว็บ แม้ไม่เคยเปิดแอพสัตว์เลี้ยง** |
| `style.css` | 24 KB | — | ทุกครั้ง |

ข้างใน `index.js` มีอะไรบ้าง:
- CSS ที่ฝังอยู่ในโค้ด (บรรทัด ~5877) ประมาณ **254 KB**
- คอมเมนต์ประมาณ **268 KB** (14%)
- ไอคอน SVG 86 อัน รวมประมาณ **375 KB**
- ข้อความภาษาไทยในหน้าจอประมาณ **500 KB** อันนี้ตัดไม่ได้ เพราะเป็นเนื้อหาจริง

ลองบีบไฟล์ (minify) จริงแล้ว:
- ตัดแค่คอมเมนต์กับช่องว่าง เหลือ **1.49 MB** (gzip 374 KB)
- บีบเต็มที่ เหลือ **1.40 MB** (gzip 352 KB)

แปลว่าบีบอย่างเดียวลดได้แค่ราว 25% ไม่ใช่ทางหลัก

### ต้นเหตุที่น่าจะทำให้เซิร์ฟเวอร์หน่วงจริง (เรียงจากหนักไปเบา)

1. **ข้อมูลมือถือทั้งหมดถูกส่งขึ้นเซิร์ฟเวอร์ทุกครั้งที่บันทึก**
   - ข้อมูลอยู่ใน `extensionSettings` ทั้งประวัติแชททุกห้อง ฟีด ประวัติโทร และ log
   - `saveCfg()` ถูกเรียก 511 จุด แต่ละครั้งสั่ง `saveSettingsDebounced()` ซึ่งส่ง `settings.json` **ทั้งไฟล์** ของผู้เล่นคนนั้นขึ้นเซิร์ฟเวอร์
   - คนที่เล่นมานานอาจมีไฟล์หลาย MB พอ 30 คนเล่นพร้อมกัน เซิร์ฟเวอร์ต้องรับและเขียนไฟล์ใหญ่ซ้ำ ๆ ตลอด
   - **ต้องยืนยันก่อน:** ขอขนาดไฟล์ `data/<ชื่อผู้ใช้>/settings.json` ของคนที่เล่นหนักสัก 2-3 คน
2. **`pet-assets.js` 3.8 MB โหลดทุกครั้ง** ทั้งที่ใช้แค่ตอนเปิดแอพสัตว์เลี้ยง
   - ทุกครั้งที่อัปเดต extension ผู้เล่นทั้ง 30 คนต้องโหลดใหม่หมด ครั้งละ ~2.9 MB × 30 = ~86 MB
3. **`index.js` ใหญ่** อันนี้มีผลน้อยสุด เพราะเบราว์เซอร์เก็บแคชไว้ รอบถัดไปเซิร์ฟเวอร์แค่ตอบว่า "ไม่มีอะไรเปลี่ยน"

### แผนลดขนาด (คุณภาพเท่าเดิมทุกอย่าง ไม่ตัดฟีเจอร์)

**ระยะ P0 — ปลอดภัย ไม่เปลี่ยนพฤติกรรมเลย (แนะนำให้ทำก่อนอย่างอื่น)**
- [ ] P0.1 โหลด `pet-assets.js` **ตอนกดเปิดแอพสัตว์เลี้ยงครั้งแรก** แทนตอนเปิดเว็บ ผู้ที่ไม่เล่นสัตว์เลี้ยงประหยัด 3.8 MB ทุกครั้ง
- [ ] P0.2 ย้าย CSS 254 KB ออกจาก `index.js` ไปไว้ใน `style.css` เพราะ manifest โหลดไฟล์นี้ให้อยู่แล้ว และแคชแยกกัน
- [ ] P0.3 รวม SVG ที่ซ้ำกัน และตัดจุดทศนิยมที่เกินจำเป็นในพาธ (ไอคอนหน้าตาเหมือนเดิม)
- [ ] P0.4 แปลงรูปสไปรท์ใน `pet-assets.js` จาก base64 เป็นไฟล์ `.webp` จริงในโฟลเดอร์ `pets/` คาดว่าเล็กลงมาก และเบราว์เซอร์แคชทีละรูปได้
- ผลที่คาด: ตอนเปิดเว็บเหลือ `index.js` ~1.6 MB + `style.css` ~280 KB และไม่ต้องโหลด 3.8 MB นั้นอีก

**ระยะ P1 — แยกโมดูล โหลดตอนใช้ (งานใหญ่ ต้องมีเทสครบ)**
- [ ] P1.1 แยกแอพที่ไม่ได้ใช้ทุกครั้งออกเป็นไฟล์ แล้วโหลดตอนเปิดแอพครั้งแรก แบบเดียวกับ pet-assets
  - แอพที่แยกได้: สัตว์เลี้ยง+เกม, เว็บบอร์ด, เบราว์เซอร์, เพลง, ปฏิทินรอบเดือน, ตัวปั้นโปรไฟล์/โพสต์, หน้าตั้งค่า 13 หมวด
  - `manifest.json` ยังชี้แค่ `index.js` ไฟล์เดียวตามข้อจำกัดของ ST
- [ ] P1.2 เพิ่มขั้นตอน build: เก็บโค้ดต้นฉบับ (มีคอมเมนต์ไทยครบ) ไว้ใน `src/` แล้วสร้าง `index.js` ที่บีบแล้วสำหรับขึ้น GitHub
  - ⚠️ เปลี่ยนวิธีทำงาน: แก้ที่ `src/` เท่านั้น ห้ามแก้ `index.js` ตรง ๆ
- ผลที่คาด: ตอนเปิดเว็บโหลดแค่ core ราว 0.6–0.8 MB (ตัวเลขนี้ยังเป็นการประเมิน ต้องวัดหลังแยกจริง)

**ระยะ P2 — ลดข้อมูลที่ส่งขึ้นเซิร์ฟเวอร์ (แก้หน่วงตรงจุดที่สุด แต่ต้องตัดสินใจก่อน)**
- [ ] P2.1 เหลือไว้ใน `extensionSettings` แค่การตั้งค่า ส่วนประวัติแชท ฟีด และ log ย้ายไปเก็บที่อื่น
- [ ] P2.2 เก็บ `saveCfg()` ให้บันทึกเฉพาะส่วนที่เปลี่ยน ไม่ส่งทั้งก้อนทุกครั้ง
- ❓ **ต้องเลือกก่อนทำ:**
  - ก) เก็บในเครื่องด้วย IndexedDB — ตอนนี้รูปสติกเกอร์ก็เก็บแบบนี้อยู่แล้ว เร็วและเบาเซิร์ฟเวอร์สุด แต่**ข้อมูลไม่ตามไปอุปกรณ์อื่น** (เล่นคอมแล้วเปิดมือถือจะไม่เห็นแชทเดิม)
  - ข) เก็บเป็นไฟล์ของผู้ใช้บนเซิร์ฟเวอร์ ST แยกจาก settings — ข้ามอุปกรณ์ได้ และส่งแค่ส่วนที่เปลี่ยน
  - ทั้งสองทางต้องมีตัวย้ายข้อมูลเก่าแบบไม่ลบของเดิม

**สิ่งที่จะไม่ทำ:** ลบโค้ดเพื่อให้บรรทัดน้อยลง แล้วฟีเจอร์หายหรือพฤติกรรมเปลี่ยน

## ส่วนที่ 2 — ความสมจริงร่วมกับโรลเพลย์ (หัวใจของแผน)

แนวคิดหลัก: **มือถือเป็นสิ่งของจริงในเรื่อง** ไม่ใช่แอพลอยอยู่ข้างนอก สิ่งที่เกิดในโรลต้องกระทบมือถือ และสิ่งที่อยู่ในมือถือต้องกระทบโรล

### R1 มือถือเป็นวัตถุในฉาก
- [x] **R1.1 ขอดูโทรศัพท์** *(2.50.0)* — ตัวละครยึดหรือขอดูมือถือ ("ขอดูโทรศัพท์หน่อย")
  - ระบบส่งข้อมูลที่อยู่ในเครื่องจริงเข้า prompt เฉพาะเทิร์นนั้น เช่นแชทล่าสุด คนที่คุยบ่อย และแอคหลุม
  - บอทจะไม่แต่งเนื้อหาในเครื่องขึ้นมาเอง
  - ผู้ใช้เลือกได้ว่าจะล็อกแชทไหนไว้ ใช้รหัสหน้าล็อกที่มีอยู่แล้ว
- [x] **R1.2 แบตหมด / ไม่มีสัญญาณ** *(2.50.0 — สลับสัญญาณเองที่ศูนย์ควบคุม หรือบทหลักส่ง phone_state มา ยังไม่จับจากคำในฉากอัตโนมัติ)* — จับจากฉาก เช่นใต้ดิน ป่า หรือบนเครื่องบิน
  - ข้อความขึ้น "ส่งไม่สำเร็จ" แล้วค่อยส่งตอนออกจากพื้นที่
  - สายเข้าจะกลายเป็นสายที่ไม่ได้รับ และตัวละครรู้ว่าติดต่อเราไม่ได้
- [x] **R1.3 โหมดห้ามรบกวน / โฟกัส** *(2.50.0)* — ส่งบอกบอทว่าเราปิดเสียงอยู่ ตัวละครที่โทรมาจะเจอสายไม่ว่าง แล้วมีปฏิกิริยาตามนิสัย
- [ ] **R1.4 หยิบมือถือขึ้นมาดูในบท** — ถ้าผู้ใช้เขียนว่าหยิบโทรศัพท์ในโรลหลัก มือถือเด้งเปิดหน้าล็อกพร้อมแจ้งเตือนที่ค้างอยู่

### R2 เวลาและสถานที่ในเรื่อง
- [ ] **R2.1 นาฬิกาในเรื่อง** — แยกเวลาในเรื่องออกจากเวลาจริง (ตอนนี้ใช้เวลาจริงอย่างเดียว)
  - โรลข้ามไป "สามวันต่อมา" มือถือเดินเวลาตาม
  - มีตัวเลือกให้ยึดเวลาจริงเหมือนเดิม ค่าเริ่มต้นคงแบบเดิม
- [x] **R2.2 ออนไลน์ล่าสุด / อ่านแล้ว ตามสถานะในเรื่อง** *(2.50.0 — ออนไลน์ล่าสุดจากเวลาที่ตอบจริง)* — ตัวละครที่หลับอยู่หรือกำลังขับรถจะไม่อ่านทันที
  - ขึ้น "ออนไลน์ล่าสุด 02:14" ให้สมจริง
  - ไม่มีมิเตอร์หรือตัวเลขความสัมพันธ์ ตามกฎเดิม
- [x] **R2.3 แผนที่ / ค้นหาเพื่อน** *(2.50.0)* — แชร์ตำแหน่งแบบสด หมุดสถานที่ที่เคยไปในเรื่องตามที่บอทเอ่ยถึง ถ้าจะใช้ข้อมูลจาก lorebook ให้ผู้ใช้เลือกเปิดเอง
- [x] **R2.4 ปฏิทินเรื่อง** *(2.50.0)* — จับวันสำคัญที่เอ่ยถึงในโรล (วันเกิด นัด วันครบรอบ) ขึ้นปฏิทินอัตโนมัติ ถึงวันแล้วตัวละครจำได้และทักมาเอง

### R3 คนอื่นในโลกมีชีวิตของตัวเอง
- [ ] **R3.1 ตัวละครนอกฉากรู้ข่าว** — เรื่องใหญ่ในโรลหลัก (ทะเลาะ อุบัติเหตุ ข่าวดี) ทำให้เพื่อนที่ควรรู้ทักมาถาม
  - จำกัดตามว่าใครควรรู้ ใช้ระบบขอบเขตเดิม และมีเพดานต่อวันกันรก
- [ ] **R3.2 แชทกลุ่ม ST ↔ กลุ่มในมือถือ** — เปิดแชทกลุ่มใน ST แล้วเสนอสร้างกลุ่มแชทในมือถือที่มีสมาชิกตรงกันให้
- [ ] **R3.3 ข่าวลือแพร่** — สิ่งที่โพสต์ลงฟีดหรือเล่าในกลุ่ม ไปถึงคนที่อยู่ในวงนั้นตามลำดับเวลา ไม่รู้กันทั้งโลกทันที
- [x] **R3.4 จับภาพหน้าจอแล้วส่งต่อ** *(2.50.0)* — แคปแชทกับ A ไปส่งให้ B แล้ว B เห็นเนื้อหาจริงที่แคปไป เป็นดราม่าที่สมจริง และ B รู้แค่ส่วนที่แคป

### R4 ครอบคลุมทุกยุคทุกแนวของโรล
- [ ] **R4.1 เลือกยุคของเครื่อง** — ยุคปุ่มกด (SMS อย่างเดียว ไม่มีฟีด) / สมาร์ทโฟนยุคแรก / ปัจจุบัน (ค่าเริ่มต้น) / ไซไฟโฮโลแกรม
  - แต่ละยุคซ่อนแอพที่ยุคนั้นไม่มี แล้วบอกบอทให้ใช้แค่สิ่งที่มีได้
- [ ] **R4.2 โลกที่ไม่มีมือถือ** (แฟนตาซี พีเรียด) — ระบบเดิมมี `requireContactToInject` อยู่แล้ว เพิ่มตัวเลือก "ปิดทั้งเครื่องสำหรับแชทนี้" ในเมนูแชท ให้หาเจอง่ายกว่าเดิม
- [ ] **R4.3 ผู้ใช้หลาย persona ในเรื่องเดียว** — ต่อยอด 2.49.0 ให้แต่ละ persona มีเครื่องแยกกันได้ (คอนแทกต์/แชทแยก) เลือกได้ว่าจะแยกหรือใช้ร่วม

### R5 ประหยัดโทเคน แม้ของเยอะขึ้น
